# Tweets — Spark + Browser Automation

1. Spark is fuel. The browser harness is the car. Neither works alone. At 1000 TPS the car finally has an engine.

2. I asked Spark to deep research a GitHub profile. It navigated, extracted, and wrote the report faster than I could have opened the tabs.

3. At 67 TPS a model misclick costs 20 seconds. At 1000 TPS it costs under 1. Same error rate. Completely different product.

4. Non-deterministic browser automation is viable now. The model improvises instead of following a script. Speed is what makes improvisation cheap enough to tolerate.

5. Running 10 parallel browser research workflows and cherry-picking the best result. 6 minutes for 10 reports. This is not a workflow you build with a slow model.

6. Emergent behavior: I asked Spark to collect GitHub data. It returned what I asked for plus inferences I did not think to ask for. They were correct. Speed gives the model enough context to synthesize.

7. Browser automation has always been the right idea. The execution was slow. 1000 TPS is not faster automation. It is a different category of automation.

8. The retry loop is now a design pattern for browser agents. At Spark speeds retries are nearly free. Stop trying to build bulletproof automation. Build fast-correcting automation.

9. The model processes context faster than the network delivers pages. It stays ahead of the page loads. That is a new kind of bottleneck shift.

10. Spark for browser research. Claude in Chrome for interactive work. Browser Use for headless delegation. Different tools, same insight: the model needs a harness to do real work.

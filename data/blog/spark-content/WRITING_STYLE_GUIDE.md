# Sero (@seroxdesigns) Writing Style Guide

## Blog Style Analysis (Statistical)

### Structure

- **Average length**: ~200 lines / ~1800 words (range: 103-259 lines)
- **Frontmatter**: YAML with title, date, tags array, draft boolean, summary
- **Opening**: 1-2 paragraph personal hook. Always first person. Always based on lived experience. Never abstract.
- **Sections**: H2 headers, 5-8 per post. Clear, short labels ("What is X", "How I used it", "What it cannot do")
- **Tables**: Heavy use. Specs, comparisons, benchmarks. Markdown tables. Always concrete numbers.
- **Blockquotes**: Self-quotes from own tweets (@seroxdesigns). Used as pull quotes to reinforce points.
- **Closing**: Actionable numbered list + philosophical reflection (1-2 paragraphs)
- **No emojis. Ever.**

### Sentence Style

- Short sentences. Declarative. Often fragments.
- "That is not a typo." / "Text only." / "Just the problem, the file, the error, the ask."
- Paragraphs are 1-3 sentences. Rarely more.
- Technical terms used without explanation when audience-appropriate.
- First person singular throughout. "I built", "I tested", "I watched this happen."

### Tone

- Direct. Confident. Opinionated but evidence-backed.
- Not academic. Not marketing. Practitioner voice.
- Admits mistakes and weaknesses openly ("First three days I generated more waste than value")
- Uses contrast: old way vs new way, slow vs fast, what works vs what doesn't.

### Content Patterns

- Links to own GitHub repos and projects
- Embedded iframes for video demos (Google Drive hosted)
- External images from technical sources (servethehome, cerebras CDN)
- Personal anecdotes tied to technical claims
- Benchmark tables comparing models/hardware
- "What I would tell you" / "What I would tell someone else" advice sections

### Tags

- Typically 3-5 tags
- Common: 'AI', 'Developer Tools', specific tech names
- Format: title case strings in array

## Tweet / X Post Style Analysis

### Structure

- **Length**: 1-3 sentences, ~80-200 characters typical
- **Format**: Direct statement. No hashtags. No threads. Standalone observations.
- **Tone**: Punchy, opinionated, technical but accessible

### Patterns

- Strong declarative statements: "Roocode is the best agentic harness for LLMs right now."
- Personal experience framing: "I spent the last few days running..."
- Imperatives: "buy a GPU", "contribute"
- Contrasts/insights: "Code is dirt cheap. Architecture, moderation and quality assurance are now most important."
- Technical specifics: model names, speeds, benchmarks mixed with opinion
- Community-oriented: sharing tools, asking for contributions
- No self-promotion links (in-tweet). The tweet IS the content.

### Voice

- Same as blog but compressed. Remove all context. Keep only the insight.
- Lowercase-leaning but not strict
- Period-terminated. Not exclamation marks.
- Occasionally uses quotes around phrases for emphasis

## LinkedIn Post Style (Inferred)

- Mix of blog depth and tweet directness
- 3-5 paragraphs, ~150-300 words
- Professional but still first-person practitioner voice
- Opens with a hook/insight, expands with 2-3 supporting points, closes with a takeaway
- May include 1-2 relevant hashtags at end
- No emojis in body text

## Key Themes Across All Content

1. Speed changes workflows fundamentally (not just faster = better)
2. The harness/infrastructure matters more than the model
3. Personal experience > benchmarks alone
4. Admit weaknesses, show growth
5. Open source, community contribution
6. Hardware awareness (GPUs, Cerebras, local inference)
7. Practical tips over theory
8. "The bottleneck is you, not the model"

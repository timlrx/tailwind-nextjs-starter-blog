# Realtime Coding Tweets — Codex-Spark

1. Slow models trained me to prompt and walk away. Spark is fast enough that I prompt and read. That one second difference changed how I code more than any feature ever did.

2. With Claude Code I juggle three repos while agents run. With Spark I stay in one repo with my full attention. Speed killed the multitasking habit I did not know I had.

3. At 1000 tokens per second the model finishes before you can open another tab. That is not a small thing. That is a different relationship with a tool.

4. I started treating Spark like a keyboard shortcut. Need a utility function? Describe it. Have it in under a second. Paste it. Keep moving. That is a new category of tool.

5. The multitasking workflow — prompt, switch repos, come back, re-read, re-engage — is a coping mechanism for slow inference. The inference is no longer slow.

6. I ran Spark on my vllm-studio codebase for 40 minutes without opening another tab once. That had not happened in months of AI-assisted coding. Speed is the mechanism. Focus is the output.

7. The division of labor that actually works: you handle architecture decisions, Spark handles execution. The execution is now fast enough that it never interrupts your thinking.

8. Context switching between repos while waiting for slow models costs you 10-25 minutes of re-engagement every time. With Spark you stay. The cost is near zero.

9. This is closer to pair programming than delegation. With Claude Code I prompt and walk away. With Spark I prompt and read. The loop is tight enough to stay in the code the whole time.

10. One repo per session. One conversation. Full attention. The model keeps up with your thinking. You keep up with the model. That is how good work gets done.
